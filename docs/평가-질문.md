# B3-1 동료평가 예상 질문

## 전체 흐름

**Q. 외부 사용자가 페이지에 접속하는 과정은?**
브라우저가 EC2 퍼블릭 IP의 HTTP 80으로 요청한다. 인터넷 게이트웨이, VPC와 공개 서브넷을 거쳐 보안 그룹이 허용한 요청이 EC2 Nginx에 도착한다. 서브넷의 라우팅 테이블에는 0.0.0.0/0을 인터넷 게이트웨이로 보내는 경로가 있다.

**Q. 각 요소의 역할은?**
VPC는 분리된 가상 네트워크, 서브넷은 그 안의 구역, 라우팅 테이블은 목적지별 경로표, 인터넷 게이트웨이는 인터넷 연결 통로, EC2는 가상 컴퓨터다.

## 보안과 권한

**Q. 보안 그룹의 규칙은?**
HTTP 80은 0.0.0.0/0에서 허용하고 SSH 22는 지정 공인 IP 한 개(/32)에서만 허용했다. 공개 페이지는 모든 사용자가 열어야 하지만 SSH는 서버 관리용이다.

**Q. IAM과 보안 그룹은 어떻게 다른가?**
IAM은 누가 AWS 자원을 조회·생성·변경할 수 있는지 제어한다. 보안 그룹은 EC2로 드나드는 네트워크 통신을 제어한다.

**Q. 최소 권한을 충족했나?**
현재 실습 사용자 cdy에 전체 권한 정책을 사용했으므로 최소 권한 충족이라고 말할 수 없다. 과제 요구에 맞게 필요한 동작과 대상만 남기는 작업 및 검증이 필요하다.

## 확인과 문제 해결

**Q. 어떻게 정상 동작을 확인했나?**
SSH 접속 후 `curl -I http://localhost`에서 200, `curl -I https://example.com`에서 200을 확인했다. 외부 브라우저에서 퍼블릭 IP로 접속해 Nginx 페이지를 확인하고 캡처했다.

**Q. 권한 오류는 어떻게 해결했나?**
처음 b3-1-student의 VPC 화면에서 두 조회 권한의 액세스 거부가 발생했다. 메시지의 작업명과 정책을 대조하고 관리자가 해당 조회 권한을 추가한 뒤 VPC 목록이 보이는 것을 확인했다. 상세 과정은 troubleshooting.md를 참고한다.

**Q. 외부 접속이 안 되면?**
서브넷의 경로표와 IGW 연결, 보안 그룹 80번, 공인 IP, 웹 서버 상태 및 로그를 차례로 확인한다.

**Q. 접속자가 많아지면?**
한 대의 EC2가 처리량 병목이 될 수 있다. 여러 서버로 확장하고 부하 분산기를 고려할 수 있으나, 이 미션의 최소 구현에서는 추가하지 않았다.

## 정리와 비용

**Q. 어떤 자원을 정리하나?**
실습용 EC2, EBS, EIP, 보안 그룹, IGW, 서브넷과 VPC를 추적한다. 미생성 자원은 미생성으로 기록하고 기본 VPC 등 기존 자원은 구분한다. 실제 정리 결과는 cleanup-checklist.md에 남긴다.

**Q. 종료 후 URL은?**
실습 서버를 종료하면 캡처에 보이는 URL이 더 이상 작동하지 않는다. 재시작한 경우 자동 할당 공인 IP가 달라질 수 있다.

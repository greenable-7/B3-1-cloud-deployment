# B3-1 AWS 리소스 정리 — 혼자 따라 하는 실습 안내서

> 기준일: 2026-11-20 · 실습 리전: **아시아 태평양(서울), ap-northeast-2** · 대상: **이 미션에서 생성한 자원만**.  
> **주의:** 삭제는 되돌릴 수 없습니다. 먼저 삭제 전 증빙과 서버 내부의 필요한 데이터를 백업하세요. 기본 VPC, 다른 프로젝트 자원, AWS 계정 자체는 삭제하지 않습니다.

## 1. 왜 삭제해야 할까?

- **평가 1-1~1-4**: EC2 웹 서비스와 네트워크가 작동함을 보여주기 → **삭제 전** 증빙.
- **평가 1-5**: 실습 종료 후 최소 다섯 종류의 클라우드 자원이 정리되었음을 증명하기 → **삭제 후** 증빙.
- 해결법: **삭제 전 증빙 → 실제 삭제 → 삭제 후 목록 확인·캡처 → 체크리스트 작성 → 필요하면 새 자원으로 재구성**.
- EC2의 **중지(Stop)** 와 **종료/삭제(Terminate)** 는 다릅니다. 중지된 인스턴스는 재시작 가능하지만 일부 자원 비용이 지속될 수 있습니다. 종료된 인스턴스는 원상 복구할 수 없습니다.

## 3. 삭제하기 전 화면 증빙

각 AWS 화면에서 **리전이 서울인지 먼저 확인**합니다. **자원 이름보다 ID를 기준**으로 같은 자원인지 판단합니다.

1. EC2 → 인스턴스: `cdy` 행(상태, ID, 인스턴스 유형) 캡처.
2. EC2 → `cdy` → 스토리지: EBS ID, 크기, `종료 시 삭제` 설정 캡처.
3. EC2 → 보안 그룹: `sg-0c2b0be06285043eb`의 HTTP 80/SSH 22 규칙 캡처.
4. VPC 콘솔 → VPC / 서브넷 / 라우팅 테이블 / 인터넷 게이트웨이 각각: 이름과 **ID 및 VPC 연결 관계**가 보이게 캡처.
5. EC2 → 네트워크 및 보안 → 탄력적 IP 주소: **서울 리전 0개**인 경우 캡처.
6. 가능하면 Billing → 청구서에서 사용료와 무료 티어 차감이 함께 보이는 자료 보존.

**캡처 이름 예:** `docs/evidence/cleanup/01-ec2-before.png`, `02-ebs-before.png`, `03-security-group-before.png`, `04-route-table-before.png`, `05-igw-before.png`, `06-vpc-subnet-before.png`. 개인정보·계정 식별 정보가 포함되면 공개 저장소 업로드 전에 가립니다.

## 4. 삭제 순서와 콘솔에서 확인하는 방법

### A. EC2 인스턴스 삭제 — 이미 실제 수행

1. EC2 → 인스턴스 → **`i-081121aca74954e4e`** 선택.
2. 인스턴스 상태 → **인스턴스 종료(삭제)**. 종료 확인창에서 대상 **ID 일치 여부**를 확인.
3. 'OS 종료 건너뛰기'는 특별한 이유가 없으면 선택하지 않음.
4. 종료 요청 후 새로고침 → **`종료됨`** 표시를 캡처.
5. **실제 결과:** 2026-11-20에 `종료됨` 화면 확인 완료.

### B. EBS 볼륨 자동 삭제 검증 — 지금 해야 할 다음 작업

1. EC2 → **Elastic Block Store → 볼륨**.
2. 검색창에 **`vol-0e71dfa6e67864031`** 입력.
3. 목록에 **안 나타나는지** 확인. 표시된다면 새로고침하고 상태(`삭제 중`/`사용 가능` 등)를 확인.
4. 이 볼륨이 `종료 시 삭제 = 예`인 루트 볼륨이었으므로 EC2 종료 후 자동 삭제가 예상됨. **콘솔에서 확인하기 전에는 '삭제 완료'라고 단정하지 않음.**
5. 목록의 결과와 검색 필터/리전이 보이도록 캡처.
6. 만약 볼륨이 `사용 가능(available)`으로 남아 있으면 **정확한 ID를 재확인하고, 보존할 데이터가 없는지 확인한 다음** EC2 → 볼륨 → 작업 → 볼륨 삭제. 다른 볼륨을 삭제하지 말 것.

### C. 추가 비용 자원 확인

- EC2 → 네트워크 및 보안 → **탄력적 IP 주소**: 서울 리전에서 미생성 확인. 사용자가 직접 할당한 EIP가 나중에 발견되면 **해당 EIP만** 연결 해제 및 주소 릴리스.
- EC2 → 스냅샷: 실습에서 생성한 스냅샷 유무와 소유자를 확인. **AMI나 다른 복구에 필요한 스냅샷은 함부로 삭제하지 않기.**
- EC2 → 로드 밸런서, VPC → NAT 게이트웨이, VPC 엔드포인트, 네트워크 인터페이스: 이번 VPC에 연결된 항목이 있는지 확인. VPC 삭제를 막는 의존 자원이 있을 수 있음.
- 현재 실습 구성은 EC2 1대 + Nginx이며, ALB/NAT 등 별도 생성 증빙은 없음. **미생성 여부는 해당 목록으로 확인.**

### D. 네트워크 정리 — 두 가지 방법 중 선택

**권장: VPC 콘솔에서 이번 VPC를 삭제하고 관련 네트워크 자원을 함께 정리**

1. VPC → **내 VPC** → `b3-1-vpc`의 **ID `vpc-093f04bf3ce026d5b`** 선택.
2. 삭제 전에 **VPC 자체, 서브넷, 라우트 테이블, IGW, SG** 목록을 각각 캡처.
3. EC2, NAT 게이트웨이, 로드 밸런서, VPC 엔드포인트 같은 **삭제를 막는 자원이 남아 있지 않은지** 확인.
4. VPC 선택 → **작업(Actions) → VPC 삭제(Delete VPC)**. 대화창에서 이번 미션 ID와 함께 삭제될 자원을 꼼꼼히 읽고 확인.
5. AWS VPC **콘솔**에서 VPC를 삭제하면 해당 VPC의 **서브넷, 라우트 테이블, 보안 그룹, 인터넷 게이트웨이 등**을 함께 삭제하는 방식이 지원됨. 구성·의존 관계에 따라 별도 사전 정리가 요구될 수 있음. 기본 VPC는 삭제하지 않음.
6. 완료 후 **내 VPC 목록에서 해당 ID가 없는지**, 서브넷·라우트 테이블·IGW·SG 목록에서도 **이번 미션 ID가 없는지** 각각 확인·캡처.

**대안: 자원을 하나씩 수동 삭제하는 경우** (평가자가 각 단계의 개별 증빙을 요구한다면)

- 의존 자원 정리 → 서브넷 → 사용자 생성 라우트 테이블 → 사용자 생성 보안 그룹 → IGW(VPC에서 **분리 후 삭제**) → VPC 순서로 검토.
- 라우트 테이블은 서브넷 연결이 있으면 연결을 먼저 해제하거나 서브넷 삭제를 완료해야 할 수 있음.
- SG는 네트워크 인터페이스가 사용 중이거나 다른 SG가 참조하면 삭제되지 않을 수 있음.
- IGW는 VPC에 붙은 상태로 바로 삭제할 수 없어 **연결 해제(분리) → 삭제**해야 함.
- **기본(default) 보안 그룹과 기본 라우트 테이블은 개별 삭제하지 않음.** VPC 삭제 시 해당 VPC의 기본 구성요소는 함께 정리됨.
- 수동 방식은 단계가 많고 의존 관계 오류가 생기기 쉬워, **본 실습은 VPC 콘솔 삭제 + 자원별 삭제 후 목록 증빙**을 우선 권장.

### E. 키 페어 / IAM / 추가 자원

- EC2 → **키 페어**에서 `cdy`만 미션용인지 확인 후 필요 없으면 삭제. AWS 키 페어 삭제는 로컬 개인 키 파일까지 지우는 것은 아님.
- IAM `cdy`, `b3-1-student` 계정은 **AWS 로그인 권한에 영향을 미치므로** 실습 종료와 향후 계정 접근 계획을 확인한 뒤 별도로 판단. **루트 사용자나 AWS 계정을 삭제하지 않기.**
- EC2의 `종료됨` 목록 행은 잠시 남을 수 있음. **상태가 종료됨이면 완료 증빙으로 기록**할 수 있지만, 삭제 요청 직후의 `종료 중`과 혼동하지 않기.

## 6. 삭제 후 평가자에게 설명하는 문장

> 실습 중 EC2와 Nginx 웹사이트의 정상 동작을 먼저 확인하고 증빙을 저장했습니다. 이후 미션에서 만든 자원을 식별하고, EC2를 종료한 뒤 EBS 자동 삭제 여부와 네트워크 자원 삭제 여부를 각각 AWS 콘솔에서 확인했습니다. 삭제·미생성 항목을 구분해 GitHub 체크리스트에 기록했습니다.

**주의:** 위 문장은 **해당 단계까지 실제 완료한 다음에만** 그대로 사용. 현재는 EC2 종료만 확인됐고, EBS와 네트워크의 삭제 완료 여부는 아직 확인 중.

## 7. 실수 방지·문제 해결

- 리전이 버지니아로 바뀌면 **서울**로 변경한 뒤 다시 확인.
- AWS 콘솔에 `Access Denied`가 뜨면 삭제를 무리하게 반복하지 말고 **누락된 IAM 권한**을 확인.
- 목록에 자원이 없으면 **필터와 리전**을 먼저 점검. 필터 때문에 안 보이는 것인지 확인.
- `DependencyViolation`이면 어떤 ENI, NAT, LB, SG 참조 등이 삭제를 막는지 먼저 조사.
- EC2를 종료하면 기존 자동 공인 IP 웹사이트 주소는 더 이상 작동하지 않음. 새 EC2를 만들면 **새 IP로 README와 보안 설정**을 확인.
- 비용은 종료 직후 실시간으로 즉시 0이 되지 않을 수 있음. Billing은 반영 지연이 있으므로 나중에 최종 비용 확인.
- 자원을 다시 구성하면 **기존 ID와 새 ID는 다름**. 이번 삭제 증빙을 유지하고 새로운 자원은 별도 표로 기록.
